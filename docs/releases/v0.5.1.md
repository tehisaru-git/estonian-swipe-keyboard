# Viipio keyboard v0.5.1 — hold, emoji, and capitalization

**Experimental update.** Keep another keyboard installed. The signed ARM64 APK is intended as an in-place update from v0.5.0; the application ID and update-signing certificate remain unchanged. This release currently supports Estonian (ET) and English (EN) typing, not French.

## Changes since v0.5.0

- A letter hold shows its alternative after **300 ms** by default, matching the value displayed in the test device's Gboard settings. Preferences offers an adjustable touch-and-hold duration; this does not claim that 300 ms is Gboard's universal default.
- The inline emoji picker remains open after a successful emoji selection. Choose another emoji or tap **ABC** to return to letters; input-session teardown or the emoji toggle can also close it.
- Manual Shift changes the visible letter labels and accessibility descriptions. A quick second Shift enables Caps Lock in state-machine tests, and another Shift unlocks it. The same case is applied to swipe suggestions, not only direct taps; a rejected editor write does not consume one-shot Shift.
- **Capitalize sentence starts** is an independent, default-**OFF** preference. When enabled, it examines only a bounded, transient preceding-text window in ordinary text fields to distinguish a sentence boundary from a word boundary; passwords and specialized fields are excluded. The window is not logged or stored.
- Public repository description, issue templates and project overview use a language-neutral Viipio identity while stating the actual ET/EN scope. The original package ID is preserved for update compatibility; upstream CleverKeys attribution remains.

## Verification

- **119 scoped JVM tests across 11 active classes** and **24 Viipio Python checks** passed on the v0.5.1 source tree. The inherited broad CleverKeys suite is **not** claimed green.
- Signed ARM64: package `io.github.tehisaru.estonianswipe`, versionCode `5012`, label `Viipio keyboard`, ABI `arm64-v8a`, SHA-256 `eeec7a0bcf15f1e9bd8349d2a281b8b5e0ea3413ff97a14e6b094e10ead93659`. Its signing-certificate SHA-256 is `14fc12fab45b2f3b0b577393945bb7991f8e9bd8573c32f7844e15f936323853`, identical to the downloaded public v0.5.0 ARM64 release asset. The merged APK requests no Internet or microphone permission.
- On the shared x86_64/arm64-capable emulator, `adb install -r` updated the installed **v0.5.0 x86_64 (versionCode 5003)** to the new **v0.5.1 ARM64 (5012)** without uninstalling. The installed APK's SHA-256 exactly matched the signed ARM64 file. The public v0.5.0 ARM64 asset (versionCode 5002) was verified by checksum and signing certificate separately, **not installed as the immediate update baseline**: the existing emulator app had a higher x86_64 versionCode, and downgrading it would not be a valid update check.
- Signed ARM64 editor checks confirmed `a` with sentence capitals off, `Aa` when enabled, and `A. B` after punctuation; the new preference returned to OFF afterwards. Two emoji choices inserted `😀😀` with the picker still visible until **ABC**. A 220 ms hold inserted `m`, whereas 380 ms inserted `?`. Gboard and the launcher were restored after each test.

**Not yet established:** physical Pixel 8 touch timing for double-Shift Caps Lock, real-finger swipe accuracy or ergonomics, full inherited-suite health, and every third-party editor. ADB double-taps did not reliably activate Caps Lock in either Viipio or the reference Gboard, so they are not evidence that real double-taps fail.
