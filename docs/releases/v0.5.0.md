# Viipio keyboard v0.5.0 — one settings home and personal words

**Experimental release.** Signed APK and editor behavior were tested on an x86_64 emulator, not a physical Pixel 8. Keep another keyboard installed.

## Changes

- App icon, keyboard gear and Android IME settings point to the same English-language Settings home. Setup/practice and opt-in diagnostics are destinations there; navigating to diagnostics leaves collection OFF.
- Existing swipe-to-manual spacing remains ON by default. Double-space period is now switchable (ON by default); turning it OFF yields two literal spaces. The active keyboard also exposes switches for manual suggestions, one-press Backspace undo of an owned swipe, Backspace left-swipe word deletion and corner symbol shortcuts. The symbol layer and Estonian `š/ž` remain available when corner symbols are hidden.
- Short candidate words fill the available row evenly. When their measured natural widths do not fit, complete words scroll horizontally; dragging does not choose a candidate. Rebinding from fit to overflow and back resets the scroll offset.
- Under **Languages & personal words**, add/list/remove a 2–48-letter word for ET or EN. New entries are stored in credential-protected app-private preferences after unlock; Android automatic-backup allowlists exclude that file. The new word editor does not write the older device-protected custom-word preference; existing entries there are still read for swipe decoding. The new words also feed manual completions. A removed new word can still be available if the same word exists independently in a legacy or system dictionary.
- No informal-Estonian or English-in-ET pack was enabled by default. [Evidence and licensing boundaries](../plans/viipio-v050-settings-and-lexicon.md) distinguish subtitle counts from chat popularity; a personal `mhm` is a user choice, not a corpus claim.

## Verification so far

- **98 scoped JVM tests across 12 active classes** and **20 Viipio Python checks** passed on the final source tree. Tests include the mixed long/short fitting row, all-short equal spacing, overflow drag and fit → overflow → fit rebinding. The inherited broad CleverKeys suite is not claimed green.
- Signed ARM64: package `io.github.tehisaru.estonianswipe`, versionCode `5002`, `Viipio keyboard`, `arm64-v8a`, SHA-256 `6cdb33cb2542ad06b1ea20ac6363bbc10e334f697c561990ce731349c4c4ca74`; same SHA-256 signing certificate as v0.4.0 (`14fc12fab45b2f3b0b577393945bb7991f8e9bd8573c32f7844e15f936323853`). The merged permissions request no Internet or microphone access.
- The signed x86_64 APK updated an installed v0.4.0 without uninstalling. Installed Settings showed all active categories, actual diagnostics OFF, and ET-only add/list/remove of a synthetic `mhm` (EN stayed empty). With Viipio selected, typing `mh` offered `mhm`, and tapping it committed exactly `mhm`. After deleting the personal entry, the `mhm` candidate disappeared. A fitting one-word row stayed still on drag; an overflowing `rahvusvahel` row moved to reveal the complete `rahvusvahelisel` offer. Drag did not alter editor text, and tapping the revealed word committed exactly `rahvusvahelisel`. The personal word was removed afterwards. Separately, tapping `tere` then two Spaces produced `tere. ` with the switch ON and `tere  ` with it OFF. The other four switches were also tested in both states: typed suggestions were hidden/shown, corner hints hidden/shown while `š` still inserted, one Backspace deleted a single character/whole owned swipe, and Backspace left-swipe did nothing/deleted a word. All switches, Gboard and launcher were restored.

**Not yet established here:** physical-device comfort/accuracy, full inherited-suite health, consented diagnostic export/readback and all third-party editor behaviors. Synthetic paths are integration probes, not human accuracy data.
