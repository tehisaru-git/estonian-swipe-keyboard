# Viipio keyboard: Gboard-like typing parity roadmap

**Scope:** the *active* `EstonianSwipeService` registered in `AndroidManifest.xml:31–42`, not dormant CleverKeys keyboard/view/clipboard/voice features. This is a source/limited-emulator snapshot, **not** a physical-device audit or a claim of Gboard equivalence. v0.3.0 covers the rebrand and manually typed prefix suggestions; version numbers after that are **proposals**, not published releases.

## Evidence and priority rule

- **User reference and project requirements:** `docs/specs/estonian-swipe-ui.md:3–58,60–84,111–137` records the user-supplied dark screenshot's keyboard portion (charcoal surface, slate rounded keys, lighter modifiers, pale-blue Enter), separate ET/EN, a number row, three suggestions, offline bilingual emoji search, and the user's preference for Estonian fluency. It explicitly excludes the screenshot's Discord composer/status controls, GIF button and microphone from the required IME. These are **documented screenshot observations / prior requirements**, not fresh measurements of the image in this task. The spec says not to silently enable autocorrect when the reference has it off.
- **Official Gboard behavior, not usage data:** Google's help describes glide typing and replacement by suggestion [1]; typing a word and selecting a suggestion or configuring text correction [2]; spacebar cursor movement, double-tap Shift for caps lock, long-press accents, emoji/GIF and language switching [3]; clipboard/pins [4]; and theme/key feedback settings [5]. Google's page about suggestions also describes availability constraints for *some* Gboard suggestion features; do not infer Estonian support or identical feature behavior from that page [2].
- **Priority is a product hypothesis, not a measured usage ranking:** no telemetry, survey or credible per-feature usage counts were supplied. P0 means needed for routine ET/EN text entry or recovery from errors, P1 means convenient daily adjunct, and P2 is expressly deferred by the user. Validate priorities with consented real-device tasks, not invented percentages. Gboard is a behavioral reference only: no Google code, fonts, artwork, models, word lists, names/icons or screen tracing for redistribution.

## Incremental milestones and semantic release cadence

**Cadence:** one GitHub version per accepted *major product update*, not per internal commit. Keep v0.2.3 as baseline. v0.3.0 is the **Viipio rebrand plus live manual-prefix suggestions only**; the remaining M1 editor conveniences need separate subsequent versions, not an implicit claim that all Gboard behavior ships with the first release. Further proposed experimental milestones are v0.4.0 (editing/caps), v0.5.0 (swipe quality) and v0.6.0 (emoji/clipboard/settings) when each passes its gates. Use PATCH (e.g. v0.3.1) for verified fixes without a new capability. Reserve v1.0.0 for a separately approved physical-phone daily-use quality gate; no dates or release claims are implied. Each release candidate needs a distinct monotonically increasing Android `versionCode`, the same package ID and private signing certificate for in-place updates, source/licensing notices, a real APK install/readback and a GitHub release asset verified after publication. Do not publish merely because unit tests pass.

### M1 — P0 manual typing and correction (v0.3.0 initial slice; v0.4.0 follow-up)

- **v0.3.0 implement:** local per-language incremental tap prefix candidates in the active service; keep swipe candidates distinct and preserve typed text on rejected completion. No silent auto-replace. Handle cursor change, app switch, punctuation, Space, and password/number/URL/email gating. Retain the existing ET/EN control and established gestures. **v0.4.0 follow-up:** typo correction, caps-lock, safe sentence-start case, improved punctuation/spacing and cursor-drag without destabilizing tap/swipe arbitration. These are not v0.3.0 claims until separately built and tested.
- **Acceptance:** v0.3.0 in both languages typed prefixes yield relevant selectable completions; rejected replacement leaves surrounding text unchanged; password/no-suggestion fields show no candidates. ET `õ ä ö ü š ž` remain available, language switching changes the candidate source, and swipe suggestion replacement does not regress. The typo, caps-lock, cursor-drag and expanded punctuation checks belong to the v0.4.0 follow-up and are not first-release claims.
- **Privacy:** dictionary/completion on-device; no full editor buffer stored, logged or exported. No learning in secret fields or personalization by default; bounded cursor context and immediate invalidation on field/language/selection change. No new network permission.
- **Tests / real device:** v0.3.0 unit tests for prefix/rank and safe replacement, installed light/dark ET/EN keyboard screenshots and ordinary/controlled-editor commit checks; human Pixel 8 typing tasks and password-field check remain a separate device gate. The v0.4.0 follow-up adds typo/caps/spacing/Unicode and cursor-drag tests, TalkBack and physical touch checks. Record failures rather than treating UI visibility as a successful commit.

### M2 — P0 Estonian-first swipe quality and reliability (proposed v0.5.0)

- **Implement:** verify bundled licensed ET lexicon and EN isolation, prewarm/fallback and measured key geometry; capture/check bounded pre-swipe cursor text immediately before accepting async result, cancel on all lifecycle/selection/language/emoji changes, preserve reversible top-3 correction and one-word undo. Tune recognition only using legally usable, consented development data; do not copy Gboard's model/word data.
- **Acceptance:** fresh install and warmed ET/EN swipe → editor readback → Space/next word → alternative correction/undo work in ordinary and controlled editors; accented/inflected ET words and short ambiguous words evaluated on a held-out set. Report top-1, top-3, wrong-language suggestions, correction effort and cold/warm p50/p95 separately alongside same-device Gboard comparison; set quantitative go/no-go thresholds from baseline and user trial **before** tuning, not retrospectively. No invented target or success rate.
- **Privacy:** password/secret fields never enter a decoder or telemetry; traces stay off by default, any optional study is consented, bounded, local and erasable, with no personal sample text in Git. Verify packaged permissions/attribution.
- **Tests / real device:** decoder/geometry/epoch/snapshot unit tests, stale-field and rejection integration tests, fresh-install/minified APK emulator smoke, then genuine Pixel 8 swipe phrases in both languages with separately held-out prompts, battery/memory/crash observations and accessible correction. Synthetic ADB trajectories test wiring only, not human accuracy.

### M3 — P1 emoji, clipboard and effective settings (proposed v0.6.0)

- **Implement:** polish existing offline ET/EN emoji search and accessible picker, verify recents only on confirmed commit; add an original, explicit current-clip paste action (not inherited clipboard-history UI by assumption). Simplify settings to controls that demonstrably alter the active service; preserve usable language/dictionary setup, English UI, system light/dark and original iconography. Treat persistent history/pins as a separately approved opt-in subfeature, not a prerequisite.
- **Acceptance:** queries in both languages and typo cases return appropriate emoji offline and tap inserts one emoji while target editor remains visible; current plain-text clip pastes only after a tap, empty/media/sensitive clips do not leak or crash, no passive capture; each visible setting has a tested before/after active-IME effect. Font scaling/TalkBack/narrow portrait/landscape remain operable.
- **Privacy:** no silent clipboard listener/history, no clipboard contents in logs/telemetry/backups by default; if history is later approved, specify expiry, erase, encryption, sensitive-clip exclusion and backup policy first. Keep no Internet/microphone access; confirm *merged APK* permissions, not just source manifest.
- **Tests / real device:** packaged-asset emoji ranking/latency tests, picker and clip fakes, instrumented commit/privacy checks; physical Pixel 8 offline ET/EN search, current-clip paste, category/recents clear, settings persistence, app switching, TalkBack and light/dark screenshots. Verify installed behavior rather than legacy settings source.

### Deferred gate — P2 GIF, voice and extras (no version proposed)

Only revisit if the user reprioritizes them. GIF implies content sourcing, network and safety/licensing decisions; voice requires microphone permission, consent, locale and retention decisions. A future milestone would need explicit acceptance, privacy design, real-device and permission checks **before** a semantic version is proposed. No proprietary Google assets or API scraping.
