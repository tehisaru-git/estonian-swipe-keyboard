# Viipio next release: one settings home, optional actions, personal vocabulary

## Product contract

- The launcher icon, keyboard gear and Android's IME settings entry land on **one English-language Viipio Settings home**. Setup/practice is a named destination, not a second settings home. Privacy & diagnostics is one home row showing current collection state and opening the existing dedicated consent/export/erase screen. Navigating there never starts collection. Back returns to the same home. Only active-IME controls appear; inherited CleverKeys controls remain hidden.
- Visually follow Gboard's **category hierarchy**, not its graphics/code: on the installed Gboard, the home separates Languages, Preferences, Corrections and suggestions, Glide typing, Dictionary and Privacy; the observed Preferences → Shortcuts page contains **Double-space full stop**. Google's setup documentation also directs the user to a single keyboard Settings entry and describes language/layout and correction areas.[5] This is a black-box design reference, not proof of Gboard implementation internals.
- **Typing & shortcuts**: default-ON *Double-space inserts period and space*, default-ON *Space before first letter after swipe* (existing), default-ON *Word suggestions*, default-ON *Backspace swipe-left deletes word*, default-ON *One Backspace undoes an owned swipe word*. Separate *Long-press symbols* default-ON only if disabling them preserves an accessible path to õ/ä/ö/ü, š/ž and the symbols layer. Never show dead auto-capitalization/haptic/voice/GIF options. A switch must be read on the active service path and confirmed in a real editor, not just stored.
- Double-space is **already implemented** in `ManualTypingPolicy.space()` (verified editor/caret, ≤700 ms, `. ` replacement), but currently forced on. The new switch gates only period conversion, not the normal Space key. No conversion in password/URL/email/number/no-learning fields, across selection/cursor/editor changes, after punctuation, or if a write fails. An off switch inserts two literal spaces. Do not copy Gboard's double-space timing or code.
- **Suggestions**: short candidates share the available viewport evenly (like the original weighted strip), including a lone short word; all labels remain whole at readable text size. Switch to natural widths + horizontal dragging **only if** measured total width (including separators and font scale) exceeds the viewport. Drag never selects; tap after drag selects the correct offer. Resize/rebind recomputes fit without a scroll jump for unchanged offers.
- **Personal words**: add/list/delete explicit, validated 2–48-letter entries per ET or EN; no automatic learning from arbitrary text, no network and no global dictionary write. The user can add `mhm` to **ET** without changing everyone else's lexicon. Write new entries only into a named credential-protected, app-private preference after unlock; the backup allowlists exclude that file, so a reinstall may require re-entry. Merge the existing device-protected `custom_words_et/en` read-only for backward compatibility with both CTC and geometric adapters, and use the credential-protected entries in manual prefix suggestions; older legacy entries are not migrated or shown in the new personal-word list. Reflect a saved/deleted new word without restarting or leaking across languages. Validate size, script, duplicates and sensitive fields; test the installed settings → manual `mh` → `mhm` offer and a warmed ET swipe candidate where possible. A personal word is user-supplied, **not** evidence of corpus prevalence. Google documents a user gesture to add a word to its dictionary, but that behavior is a reference only.[4]

## Evidence and staged lexicon policy

The reproducible public `et_full.txt` OpenSubtitles-2018-derived list has **1,004,977 listed forms** and their listed counts sum to **65,751,289** (locally recomputed from the UTF-8 file, SHA-256 `8b0dbb18efd797a497878caae9597fe230be5162dcc6a39d4a35299bb8c60e14`). Exact case-sensitive rows: `okei` 23,516; `kutt` 11,830; `tsau` 2,287; `jep` 1,110; `mhmh` 181; `mhm` 111; `sorry` 308; `nice` 259; `cool` 187; `lol` 109; `bro` 60; `omg` 15.[2] This denominator is the **sum of listed word counts**, not independently verified total subtitle tokens. Subtitles are not representative of Estonian private chat; an English-looking token may have other contexts. FrequencyWords labels the *content* CC BY-SA 4.0, distinct from the MIT code licence.[1]

A study of the Estonian teenagers' instant-message corpus reports 60,000 words from 102 informants, 99 using some English, with a **7.5% average English share** and substantial variation.[3] It does **not** provide counts for `sorry`, `nice`, `cool`, `bro` or `mhm` in this excerpt. Thus no blanket English-in-ET list and no informal pack will be silently enabled or represented as a ranked chat lexicon. The separate future **Informal Estonian** and **English in ET chat** packs require per-form chat counts/denominator, licensing and native-speaker review before being offered; their default must be OFF. In this release, only individual user-added words cross the ET/EN boundary by explicit per-language choice. No raw corpus or chat data is bundled.

## Release gates

1. Test-first active routes: app icon, toolbar gear and Android IME settings metadata open the same home; setup/practice and diagnostics remain reachable; diagnostics OFF and not collected by navigation.
2. Unit + installed-editor tests for double-space on/off and fail-closed cases; toggles for every claimed optional gesture actually affect active IME without losing ET letters/symbols.
3. Robolectric native-width fixtures and signed APK screenshots: one/three short candidates distribute and cannot scroll; long candidates scroll and stay readable in light/dark; drag vs tap editor readback.
4. Personal ET `mhm` add/list/delete; `mh` completes only in ET when scoped; both swipe adapters load custom word and invalidate cache on edit; no user word in source or tests outside synthetic fixtures. Check data erasure/backup behavior explicitly.
5. Existing package ID, signing certificate, no Internet/microphone permission; scoped suites and emulator in-place upgrade; restore Gboard/system settings; tag one separate release only after artifact verification. Never describe synthetic swipe success as measured human accuracy.
