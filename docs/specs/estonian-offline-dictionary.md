# Bundled Estonian dictionary provenance and routing

The APK ships `src/main/assets/dictionaries/et_enhanced.bin`, copied without modification from `dictionary.bin` in the published `build/tooling/release-assets/langpack-et.zip` (CKDT V2, `et`, 95,000 entries; SHA-256 `9b4e79ad7ebefb59d7a23b3d719fcc62d8d8b33afa5d2638461e8a7fdfe9abe2`). Its original manifest and attribution ship alongside it at `src/main/assets/estonian/manifest.json` and `src/main/assets/estonian/NOTICE.txt` (outside the dictionaries directory, because the Gradle dictionary-generation task interprets every non-contraction JSON there as word-frequency data); repository `NOTICE` also attributes the bundled data under CC BY 4.0. The source is Leipzig Corpora Collection, processed by Helium314 in HeliBoard aosp-dictionaries; tehisaru-git selected/filtered/quantized the top 95,000 forms. Source URL and attribution are in the retained manifest/NOTICE. This does not install or replace a ZIP under `files/langpacks/et/`.

On a fresh installation, `DictionaryDataSource`, synchronous `WordPredictor`, and `AsyncDictionaryLoader` already probe installed packs before `dictionaries/${language}_enhanced.bin`, so et resolves to this bundled asset for tap prediction. `GeometricEngineAdapter.dictionaryFor` likewise checks `files/langpacks/et/dictionary.bin` first, then the bundled binary. `CtcLanguageSupport` serves the bundled binary with the CKDT-scale Latin preset on a fresh install; when the installed-pack resolver declares an et pack eligible, CTC selects the installed pack instead, without changing any other bundled CTC language. The eligibility verdict is asynchronous, so during first measurement after import CTC may temporarily use the bundled fallback; tap and geometric readers use the installed pack immediately. A rejected/ineligible pack remains intact on disk, but CTC uses the fallback. The pack is never silently imported or overwritten.

This provides vocabulary, not measured Estonian swipe accuracy. CTC uses a transferred Latin preset, and the geometric route uses its existing generic decoder. No Estonian human-swipe accuracy corpus or device end-to-end test is established here.
