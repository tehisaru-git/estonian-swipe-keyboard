# Local Estonian swipe diagnostics (experimental)

Open **Estonian Swipe → Swipe diagnostics**. Collection is **OFF** on a fresh install. Read the consent dialog and tap **Start local collection** only if you want to record test data. While ON, the keyboard stores accepted *Estonian swipe* paths in ordinary text fields, their key geometry, top suggestions and committed words. A verified Backspace removal is marked as `undoObserved` immediately; it is not called a final deletion unless the keyboard can still verify that state. An alternate candidate or manually retyped replacement can then be linked to the same swipe. Ordinary manual typing unrelated to a swipe is not logged. Some editor updates cannot be verified, so a row may have no final word; do not interpret that as an unchanged word. Collection works across ordinary apps, not only the separate Swipe study screen.

**Privacy:** An ordinary text field may contain personal words; test with nonpersonal phrases and review any exported file. Password, email, URL, numeric, incognito and no-learning fields are excluded. English swipes are not recorded. There is no automatic phone-to-server link, upload, Android Internet permission or collection of surrounding editor contents. Events are stored in app-private, no-backup files, each encrypted with an Android Keystore AES-GCM key; a bounded in-memory representation exists while the keyboard process runs. Exports contain at most the latest 5,000 swipes from the last 30 days. Encrypted append-only segments use at most 48 MiB; expired or evicted records can remain encrypted in a partly used segment until that segment rotates or you tap Erase. The exported JSONL strips source-app package and field identifiers. A consent marker and encrypted file are never included in cloud/device backup allowlists.

Tap **Stop collection** to stop new events while keeping existing data. Tap **Erase local data**, then confirm, to stop and remove the encrypted store and key; it cannot delete files you previously exported. If a store is corrupted or its key is lost, the keyboard disables recording rather than silently resetting the store; use Erase to recover.

To send a test file for analysis:

1. Tap **Export JSONL file** and choose a local location, for example **Downloads**. This creates a **readable plaintext file** only where you chose; avoid a cloud-backed document provider if you want it to remain local. The export is not sent to the developer automatically. The separate **Swipe study → Export JSON** saves a different, prompted in-memory test session.
2. Review the file yourself before sharing; a swipe word may be personal. Connect and unlock the phone via USB. Use Android's file-transfer mode to copy the exported file, or, if *you* authorized ADB debugging and saved to Downloads, use `adb devices -l` followed by `adb pull /sdcard/Download/estonian-swipe-diagnostics.jsonl DESTINATION` on the receiving Linux computer. Check the actual document-picker filename/path first. USB connection alone does not grant the server access to app-private encrypted files or this export.
3. Send or analyze only the chosen export. JSONL contains one JSON object per accepted swipe, with normalized path coordinates and time offsets, keyboard dimensions/key rectangles, candidates, the committed word, corrections and (where verified) a final word or deletion marker. It does **not** contain a recording of everything you typed. When done, erase local data and any exported copy you no longer want.

The feature and swipe accuracy remain experimental. It has not been benchmarked by human-finger Pixel 8 trials. Avoid using this test keyboard for secrets or important messages until you have checked it in your own apps.
