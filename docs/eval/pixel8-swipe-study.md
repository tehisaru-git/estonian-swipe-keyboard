# Pixel 8 swipe quality study (opt-in)

The emulator's straight-line gestures and top-1 suggestions are not a measure of a person's Estonian swipe accuracy. A real study should use a dedicated practice field, fixed nonpersonal prompts, and an explicit local export—not passive capture in chat, browser, password, or other apps.

## Proposed session

1. On the Pixel 8, open **Swipe study** from the app's main screen, tap **Start**, and swipe each prompted word naturally in its test field. The study cycles through 20 Estonian and 8 English fixed nonpersonal words; switch the ET/EN key when the language changes. It accepts only the matching language and field. Use complete blocks rather than selecting only successful examples.
2. The current export contains relative timestamped x/y points, measured key-surface dimensions and key rectangles, language, fixed prompt, whether the expected word was at rank 1–3 (0 means absent), and the device-side time from finger lift to decoded result. Other recognized candidates are exported only when they belong to the fixed prompt list; arbitrary editor and candidate text is omitted. It does **not** yet include correction actions, committed text, orientation or a true end-to-end editor-commit duration. Do not enter private text in the study field. The session stays in memory until the user taps **Export JSON** and selects a local destination; **Clear** or closing the activity discards it; leaving the screen stops capture but retains the in-memory session if the activity survives.
3. Compute top-1/top-3 on recorded, completed decode callbacks with denominators; no-result timeouts, swipes rejected by the editor, dropped events, correction rate and p95 of end-to-end commit are **not** currently captured reliably, so don't claim a full human accuracy metric from this first export. Phone-side `decodeDelayMs` is device uptime from lift to callback; ADB's multi-command synthetic swipes still invalidate performance numbers. Repeat controlled blocks on the phone to separate cold and warm behavior.
4. Send the explicit export as a Discord file attachment in this thread after reviewing it. A redacted screen recording showing the actual key trail and suggestion behavior can supplement the export, but do not record passwords, conversations, notifications or other people's text. The user can delete the local file afterwards.

No Pixel 8 is connected to this workspace's ADB (only the shared emulator is attached). We cannot reach into a personal phone or Gboard for traces remotely. Wireless debugging would require device-side pairing approval and exposes more of the phone than this narrowly scoped study needs; do not request or enable it merely for swipe telemetry. Gboard is proprietary; inspect publicly documented or observable interaction behavior, not copy its source or assets.
